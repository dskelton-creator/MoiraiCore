What it is

One control plane for the AI work you already run.

Most people glue together several AI tools and hope results hold together. MoiraiCore is the opposite: a single, self-hosted platform that plans the work, assigns capable agents, governs every generated change, and keeps a searchable record of what happened — all without sending your data to a vendor.

How it works

A three-tier agent model with a release engineer built in.

Not one all-powerful agent — a governed team where each tier does one job well. MoiraiCore (Tier 1) plans, Tier 2 architects and generates, Tier 3 executes and repairs locally, and ScrumGate reviews everything before it merges.

TIER 1 · DIRECTOR / SCRUMMASTER

Strategic layer

plans · assigns · evaluates

Owns the backlog and decomposes goals into tasks. Assigns work to Tier 2 (architect) or Tier 3 (builder) using keyword + LLM routing, then evaluates artifacts against merge gates. The model never decides what to build next — MoiraiCore does.

  • Backlog: goals → task decomposition
  • Assignment: Tier 2 vs Tier 3 routing
  • Evaluation: PASS/FAIL artifact gates
  • Reporting: delivery status synthesis
tier1_model = director
TIER 2 · ARCHITECT

Designs & generates

provider-agnostic LLM backend

A provider-agnostic engine that produces implementation plans and code artifacts. Defaults to DeepSeek via OpenRouter; swap in Gemini or Antigravity as alternatives via env vars — no code changes.

  • Implementation plans / blueprints
  • Code generation & large tasks
  • Provider failover built in
  • No hardcoded vendor lock-in
TIER2_PROVIDER=openai
TIER2_MODEL=deepseek/deepseek-v4-flash-0731
TIER2_BASE_URL=openrouter.ai/api/v1
TIER 3 · BUILDER

Executes & repairs locally

local Ollama worker

A local model handles bounded micro-fixes, single-file edits, and test-driven fixes without leaving the machine. Fast iterations that stay on-device and never cost an API token.

  • Micro-fixes & small refactors
  • Single-file edits
  • Test-driven repair loops
  • Fully offline execution
tier3_model = qwen2.5-coder:14b · Ollama
▸ SCRUMGATE The merge queue. Every generated change is evaluated — syntax ✓ security ✓ structure ✓ — and merged to protected src/ only on approval. Direct writes are blocked.
generate→ evaluate→ merge · no bypass · no unreviewed merges · no black-box commits

ScrumGate rules: no writes to src/ without a DONE evaluation · all generation via Tier 2/3 · merge queue only · evaluation required before merge · the LLM creates tasks & submits artifacts, never writes src/ directly.

Requests enter through the dashboard or Hermes Bridge, are planned by the Director (Tier 1), executed by an architect or builder, and land behind the ScrumGate — never straight into your source.

How to use it

From zero to running in five minutes.

Install dependencies, set one API key, run one command — then the first-launch wizard walks you through creating your admin account and configuring your models.

01

Initial setup

Get the code, install dependencies, and start the server.

  1. git clone from GitHub
  2. pip install -r requirements.txt
  3. Set a Tier 2 API key (OPENROUTER_API_KEY)
  4. Run python3 scripts/server.py --port 7878
  5. Open http://localhost:7878
02

First-run wizard

MoiraiCore walks you through onboarding on first launch.

  1. Create your admin account — local username/password, or Sign in with Google (the first account becomes admin)
  2. System configuration — instance name, workspace directory, and the default Tier 1 / Tier 2 / Tier 3 models
  3. Done — config saved to config/system.json, Mission Control opens

Returning users: Settings → Setup & SSO.

03

Everyday usage

Run real AI work through one governed workspace.

  1. Create goals — the goal engine decomposes them
  2. Chat with Jarvis — conversational intelligence with personality + session memory
  3. Manage specialist agents — route work to the right specialist
  4. Track on the kanban — tasks move through the board
  5. Organize workspaces — isolate customer/project spaces over HTTP

INTEGRATION · HERMES BRIDGE

Hermes Bridge

hermes_bridge.py is a CLI wrapper that connects mission control to a general-purpose agent. Every query is routed to the best agent (researcher, writer, developer, hermes), agent memory is loaded as context, and every action is logged.

  • ask "…" — one-off query with optional --route / --log
  • route "…" — see which specialist picks it up
  • orchestrate "…" — multi-agent pipeline
  • resume <session> — continue a conversation
  • sessions / history / status
INTEGRATION · GOOGLE SSO

Google single sign-on

Sign in with Google instead of a local password. Uses OAuth 2.0 with PKCE — only the Client ID is needed, never a client secret. Configured in the setup wizard or Settings → Setup & SSO.

  • Create an OAuth Web application in the Google Cloud console
  • Authorized redirect URI: http://localhost:<port>/api/auth/google/callback
  • Paste the public Client ID into the wizard
  • First account to complete setup becomes admin

▸ RECOMMENDED CONFIGURATION
  • ✔
    Enable the Gemini fallback for Tier 2 resilience. Set TIER2_PROVIDER=gemini and GEMINI_API_KEY=… alongside OpenRouter so the pipeline keeps running if the primary path stalls.
  • ✔
    Keep TIER2_MAX_TOKENS at 8192+ for reasoning/architect models — too-small budgets truncate plans and cause rework.
  • ✔
    Run Tier 3 on a machine with ~26 GB+ RAM for comfortable local qwen2.5-coder:14b inference; drop to a smaller 7B/8B quant on lower-spec hardware.
  • ✔
    Add Antigravity (Google Pro) as a Tier 2 alternative for parallel sub-agent / heavy coding sessions — route with the antigravity agent trigger (parallel, multi-agent).
  • ✔
    Use Codex for key-free code generation — authenticate once via Settings → OpenAI OAuth with your ChatGPT account to avoid a paid API key for pure code tasks.
  • ✔
    Use the correct Google redirect URI — http://localhost:<port>/api/auth/google/callback — or Google sign-in silently fails. PKCE means only the Client ID is needed.
  • ✔
    Route by intent, not by guessing. Trigger routers on keywords — research/analyse → Researcher, write/blog → Writer, fix/debug → Developer, pipeline/orchestrate → Project Manager.
  • ✔
    Keep secrets out of git. Credentials live in .env / config/auth (git-ignored); customer projects and private vault content are intentionally excluded from the public repo.
